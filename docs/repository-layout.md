# 共享仓库与本地资料

## 文件归属

| 路径 | 是否纳入 Git | 内容 |
| --- | --- | --- |
| `AGENTS.md`、`README.md`、`docs/` | 是 | 工作约定、通用经验、流程、空白模板 |
| `.agents/skills/` | 是 | 去除任务历史与客户参数的通用技能，保留第三方许可 |
| `tools/design_library.py` | 是 | 与客户无关的组件检索、预览入口生成及结构检查 |
| `design-library/components/`、`foundations/`、`sources/` | 是 | 可共享源码、通用占位图、基础样式和许可 |
| `design-library/foundations/fonts/*.ttf` 等字体二进制 | 否 | 首次预览时从固定官方来源下载的本地缓存；共享的仅为字体清单、许可和下载器 |
| `input/`、`output/` | 否 | 原始资料、客户图、生成媒体、原生稿、PDF、交付包 |
| `validation/`、`feedback/` | 否 | 客户版式数据、任务脚本、截图、测试副本和检查证据 |
| `.local/`、`albums/` | 否 | 当前状态、任务日志、画册记忆、未经确认的经验、迁移备份 |
| `design-library/v1/` | 否 | 保留原样的本地旧库，包含客户照片、参考图及复现记录 |
| `tools/nutria-mcp/` | 否 | 当前机器的独立 Git 工作区及尚未抽取的本地修补 |

排除整个资料目录，不用 `*.png`、`*.pdf` 等扩展名一刀切，以便以后纳入有明确来源的公共示例。通用组件内不放客户照片；公开示例使用原创占位图或有明确再分发许可的素材。

`.gitignore` 不会取消已有跟踪。若以后在已有仓库应用这些规则，先检查 `git ls-files`；对确认的资料目录执行 `git rm -r --cached -- <目录>` 仅移出索引，保留工作文件。已推送的历史需要另行处理，不能声称加了忽略规则就清除了历史。

## 第三方运行时

现有 Nutria 目录是带本地修改的独立仓库，不能直接当作普通目录 `git add`，也不能为整理本项目而重置或删除它。本次不改变其源码和状态。技能所述批量排版接口包含本地扩展，干净的上游版本不保证具备同样能力。

正式分享运行时前，单独抽取不含客户路径的补丁及测试，记录上游提交与依赖版本，按原许可证保留声明，再决定用补丁、fork 或子模块发布。此项尚未完成；当前根仓库只承诺文档与组件选型工具可独立使用，不承诺新的机器已能重建历史画册。
