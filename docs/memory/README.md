# 日志、反馈与持久经验

## 三种记录

| 记录 | 位置 | 用途 |
| --- | --- | --- |
| 任务日志 | `.local/任务日志.md` | 按次追加做了什么、证据、结果、待办；保留历史状态 |
| 当前画册经验 | `.local/albums/<album-id>/MEMORY.md` | 品牌、语种、字体、版式参数、禁用项、用户偏好及本册已确认规则 |
| 项目全局经验 | [global.md](global.md) | 适用于不同画册、经用户明确确认的长期规则 |

`.local/STATE.md` 只保留当前画册、日志和最新可用版本入口；它不是又一份日志。历史版本中的“待收集”“已完成”不覆盖新指令和实际文档状态。没有 `.local/` 的新克隆从空白模板建立记录，不要求复制任何客户案例。

## 新反馈的处理

1. 按[反馈模板](../templates/feedback.md)记录原话、页面／对象、截图位置、实施范围与收集状态。用户要求收齐统一处理时遵守批次，不因拆分编号达到了数量就提前改稿。
2. 已授权的局部修改直接推进；提出意见本身可以授权该项修改，不等于授权把它保存为跨任务规则。记录事实和技术证据无需重复询问。
3. 发现适合复用的经验时，先拟出完整规则，说明触发条件、例外和范围，并去掉本次客户名称、坐标等偶然参数。候选只记在本册反馈或日志中，状态为 `pending`，不写入生效经验文件或技能。
4. 向用户展示拟保存文本并询问范围，例如：

   > 建议保存：“多图组的图注紧随对应图片下方，并与图片左缘对齐；独立的目录索引另按其用途处理。”适合保存为「项目全局经验」、「仅当前画册经验」，还是「本次修改即可」？

5. 只有用户确认后才写入所选文件。用户已明确说“记入全局经验”或已批准同一条规则和范围时，已有授权有效，直接保存，不重复确认。没有回复、技术通过、反复出现或 Agent 判断合理都不算确认；等待时继续不依赖此项的工作。
6. 保存时按[规则模板](../templates/persistent-rule.md)登记稳定 ID、范围、状态、确认时间／依据、例外、检查方法及替代关系；反馈条目回链规则 ID。全局文件只留去客户化的正文，截图、原话和私有来源保存在本地。更改规则含义、扩大范围或将本册规则提升为全局，重新确认受影响部分。

## 读取与冲突

先识别本次画册，再读全局经验、本册 MEMORY 和最新状态；按任务需要查历史日志，避免每次加载全部记录。候选、废弃与已替代规则不执行。优先级为：用户当前明确指令 → 本册已确认规则 → 项目全局已确认规则 → 技能的通用方法 → 组件演示参数。实际打开文件状态高于旧快照；用户当前稿先保护后续作。

日志中的任务成功不自动成为长期规则。组件原生验证、Agent 看图、用户视觉认可和印刷放行分别记录；同一组件在某一画册通过也不升级整个组件库的生产状态。
