# 组件库的实际使用

入口为[设计组件库](../../../../design-library/README.md)，结构与字段见[组件约定](../../../../design-library/CONTRACT.md)。共享目录是 `design-library/components/`，本地历史库 `design-library/v1/` 不进 Git；不能从旧库直接打包客户照片或用户参考截图。

字体二进制也不随项目分发。首次需要预览时使用gallery或fonts命令从固定官方来源下载、校验并缓存；离线可用gallery --offline回退系统字体，不能把回退效果当作指定字体的排版验证。来源及缓存见[字体准备](../../../../design-library/foundations/fonts/README.md)，纯检索与静态检查不触发下载。

## 从内容到组件

1. 先读取本册已确认方向、语种／英文装饰许可、标题层级、网格与色板，再识别本页的信息角色、实际条目数、完整字数和图片比例。
2. 用 `python tools/design_library.py select --category <类别> --query <关键词>` 缩小范围；需要本地旧库时加 `--include-local`。这只查本地元数据，不自动认为候选已通过原生验证。完整浏览用 `list`，详情用 `show ID`。
3. 读取候选的 metadata、component.html、component.css 及关联SVG，比较 useWhen、contentCapacity、slots、geometry、来源和验证状态。复制到本册独立工作目录后适配，保持来源与 revision；不修改共享默认值来存本册内容。
4. 保留完整文案和实际语种，替换图标、数值／单位、图片、颜色及字体。超容量时重排、续排、换组件或自由设计，不删客户文字。相同层级使用协调的组件，不把同一标题外观套给不同层级。
5. 按实际宽度渲染完整内容，看图检查图标轮廓内距、基线、文字曲线边界、组内／组间距和图片裁切；换图标、改比例、数量或长文案后重新检查。
6. 按实际DOM／布局结构映射原生文字、形状、链接图及裁切；验证可编辑、自动换行、零溢出、Story顺序与IDML保留，再看整页与真实跨页。
7. 按[组件使用模板](../../../../docs/templates/component-usage.json)在本册保存选型理由、版本、来源ID、适配参数、检查及证据；某册通过不能自动升级全局组件状态。

## 组件使用、图片主次与色板

- 组件可选，不追求使用数量；相邻页的结构变化与同级系统的一致性一起考虑。
- 演示色、英文和文案不代表本册许可。基础色板在新方向规划中确认，已确认色板内的局部适配不逐项重复询问。
- 单张亮点图片可按比例和质量成为通栏、整页或跨页主视觉；多图等大规则不限制单图。检查实际主体、标牌、有效PPI及中缝，重要人物和文字避开装订损失。
- 真实数据图、概念关系图、流程图分别选型；面积、连线、编号的含义与实际内容一致。不能将无数量意义的概念环图用作占比图。

## 扩充库

用户参考只在本地保留来源与原图。抽取几何和语义关系，使用可替换的演示插槽制作候选，记录来源及可分享性；授权未明的参考转化先留本地。不把截图直接当成组件，不从截图猜政策或正文。

可共享组件应有完整来源与必要许可、纯静态HTML/CSS/SVG、容量及几何说明、可读的原生映射边界。加入后更新 registry 和运行 check；源码、预览、用户认可和原生验证分别记录。新设计若要成为持久经验，仍按用户确认流程处理。
