# 视觉反馈与经验提炼

流程的唯一维护入口是[日志、反馈与持久经验](../../../../docs/memory/README.md)。本文件不保存当前客户状态或重复历史日志；本册原话、截图与处理结果在忽略的 `feedback/` 或 `.local/albums/<album-id>/` 内。

## 接收和实施

- 按[反馈模板](../../../../docs/templates/feedback.md)记录原话、实际页码／Spread／对象、原图及可选摘要，区分用户要求、Agent观察和方案。
- 用户要求收齐后统一改时，原样累计并记录是否提完；一张图可能有多项意见，不能按内部拆分项数冒充批次收齐。
- 已授权的具体修改直接执行；修改前保护真实现场，建立独立版本，按页对应实施和证据，不用旧 JSON 重建覆盖手改。
- 复核整页／跨页及全书同类问题，同时保持本册文案与正文参数；不要把一页坐标或一种外观变成所有画册要求。
- 结论为“已实施待用户评价”时保持该状态，Agent自查与技术检查不能填写为用户认可。

## 何时形成长期经验

发现有复用价值的内容，先拟出规则、适用条件、例外和建议范围，按共享流程询问「项目全局／仅当前画册／仅本次」。确认前候选仅留本地反馈或日志，不能写入生效经验或本技能。用户已明确要求保存同一条规则与范围时，无需重复询问。

确认后全局规则写 `docs/memory/global.md`，本册规则写 `.local/albums/<album-id>/MEMORY.md`，按[规则模板](../../../../docs/templates/persistent-rule.md)登记ID、依据与替代关系。私有原话、客户参数和截图留本地；技能只引用规则和维护执行方法，不再沉积任务日志。
